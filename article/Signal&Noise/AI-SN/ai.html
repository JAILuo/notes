    1. introduction

    本文纯 AI 生成，自嗨，因为是突然发现自己微信公众号的关注+阅读量变多了，加上看了一些知乎文章，内心其实有一些波动的。所以本文和 GPT 聊了下。

    即将入职某公司的SoC底软。

    但最近看了一些别人的文章，讲述自己工作与爱好。

    1.1 回答一

    回答来自：

    为什么碰到几个做嵌入式开发的人都说做 MCU 开发没什么意思，要做 MPU (Linux) 开发：https://www.zhihu.com/question/313859064/answer/2023851292003418735)

    如果你是指钱，其实是看行业，mcu开发赚钱的行业也很多。

    如果你是指技术，那么我很遗憾告诉你，别做梦了，做Linux也照样没意思。

    拿嵌入式通信行业来说，做路由器的，无非就是在openwrt这些上改改配置，做交换机的，天天去厂里转几圈，抓点包调试。

    面试的时候双方都在扯淡，还问什么DPDK，扯什么cfg802子系统。

    进去一看，

    人均水平连编译原理都没听过，领导和同事都拿AI当脑子用。

    遇到的麻烦问题就是哪位同事写的代码忘记释放内存了。

    你可能会说是你接触的行业太low了，不够底层。

    做Linux内核也这鸟样，看起来是国内名列前茅，人模人样的公司，进去一看，大部分自称内核开发，里面干的都是一些维护的活，没事天天用新出的编译器编译一下内核，加几行头文件消除一下警告，然后发个邮件，一年水一堆提交，自称自己多么多么牛逼，好像为内核做出了多么多么大的贡献。

    还有什么做编译器的，也都是这鸟样，大伙都是拧螺丝的业务工，谁也别嫌弃谁。

    工作都没意思。

    我现在仍然保持这个观点：如果你真的喜欢一个东西，千万不要把它变成工作，否则你只会有无穷无尽的痛苦。

    爱好必须是纯粹的，不求回报的，能够发自内心感受到快乐的。

    当你指望你的爱好为你带来什么回报时，你的爱好也就永远不在了，你也变成了一个无聊透顶、跟周围人一样死气沉沉且无趣的人，我甚至有点偏激，我觉得这种人已经变成了海德格尔笔下的一种符号化的人。

    我现在对工作已经几乎没什么期待和幻想了，我工作的唯一目的就是混口饭吃。

    2. AI 回答（鸡汤文）

    我认真看完了你的描述，以及你贴的那两篇文章和知乎回答。

    我感觉你现在遇到的，其实不是「该学什么技术」的问题。

    而是一个更底层的问题：

    你正在从一个“学生型技术爱好者”向“职业工程师”转变。

    而这个阶段最大的痛苦，就是发现：

    热爱、成长、赚钱、影响力、职业发展，这四件事并不总是同一个方向。

    所以我想从 First Principle（第一性原理）来拆。

    第一层：你到底要什么？

    你现在脑子里其实同时存在四个目标：

    目标1：成为优秀/合格的BSP工程师

    你马上去 xx 公司 的SoC 底软。

    你希望：

    • 技术能力合格
    • 能解决复杂问题
    • 未来跳槽有竞争力
    • 工资上涨

    目标2：继续保持对 Computer System 的兴趣

    你很明显不是为了找工作才学：

    • ELF
    • Linker
    • Stack Unwind
    • DWARF
    • Linux Kernel
    • RootFS
    • BSP

    你写的文章我看得出来。

    这些东西你是真的觉得有意思。

    这和很多人不一样。

    目标3：做个人IP

    公众号。技术输出。建立影响力。以后可能：

    • 技术博主
    • 咨询

    等等

    目标4：赚钱

    阅读量。赞赏。广告。课程。副业。

    问题来了，很多人潜意识里认为：

    热爱 = 成长 = 影响力 = 赚钱

    实际上：

    热爱 ≠ 赚钱

成长 ≠ 阅读量

影响力 ≠ 技术深度

职业能力 ≠ 公众号数据

    这是很多技术人痛苦的来源。

    第二层：公众号让你焦虑的根源是什么？

    你自己已经发现了：

    隔一会就看点赞，看阅读量，看数据

    为什么？因为你的大脑开始把 写文章 变成了 获得反馈

    原来是：

    研究 ELF
↓
觉得有趣
↓
写文章

    现在：

    研究 ELF
↓
写文章
↓
阅读量多少？

    奖励机制变了。

    以前：奖励来自学习。

    现在：奖励来自流量。

    这是非常危险的。

    因为：流量和价值不是一个函数。

    很多高价值文章：100阅读

    很多垃圾文章：10W+

    如果长期让大脑建立：价值 = 阅读量

    最后会被平台驯化。

    第三层：你现在最大的优势是什么？

    其实不是技术，是：你还保留着技术好奇心

    这东西极其稀缺。你发的那两个知乎回答。其实说的是同一个东西。

    第一个人说：

    工作没有想象中有意思

    对，他说的是事实。

    第二个人说：

    学习是快乐的

    工作未必

    也对。因为：

    学习

    你可以自由探索：

    • 编译器
    • CPU
    • ELF
    • MMU

    工作

    你要解决：

    if (xxx)
    return -EINVAL;

    为什么客户现场崩了。

    为什么供应商改坏了。

    为什么领导催上线。

    工作本质：创造价值

    不是：满足好奇心

    所以：不要期待工作满足所有热爱。

    这是第一原则。

    第四层：对于即将入职公司的你

    我认为未来三年最重要的事情：主线只有一条

    成为优秀的SoC/BSP工程师。别分心。

    很多人刚毕业，想同时：

    • 学技术
    • 做副业
    • 做公众号
    • 做IP
    • 赚外快
    • 做课程

    最后啥都没做成。

    你的情况恰恰相反。

    你已经找到了一个非常好的赛道：

    SoC底软
↓
BSP
↓
Kernel
↓
System

    这是一条很深的护城河。

    所以未来三年：

    80% 精力 = 工作能力
15% 精力 = 技术输出
5% 精力 = 变现

    而不是反过来。

    第五层：你现在最大的误区

    这一段我觉得特别重要。

    你说：“我想写电源管理”

    但是觉得：

    没项目经验

    不够深入

    于是焦虑。

    其实你把：经验 和 输出 搞反了。

    不是：

    经验够了
↓
开始输出

    而是：

    学习
↓
输出
↓
发现漏洞
↓
继续学习
↓
继续输出

    循环。

    你写的：

    《ELF符号表》

    《Linker Script》

    《Stack Unwind》

    本质就是这样。

    你不是专家以后才写，而是：

    写
↓
逼自己理解
↓
变成专家

    这是很多优秀技术博主的成长路径。

    第六层：如果我是你

    未来两年我会这样安排

    主航道

    工作

    目标：

    成为团队Top 20%

    重点：

    • Linux Kernel
    • Device Driver
    • Power Management
    • Scheduler
    • Memory
    • Boot Flow
    • Android Framework接口

    第二航道

    持续输出

    但规则变成：

    只记录自己踩过的坑

    例如：

    某次Crash分析

    写。

    某次内存泄漏

    写。

    某次Suspend失败

    写。

    某次驱动初始化异常

    写。

    不要为了发文而发文。

    第七层：我推荐你建立一个体系

    你其实已经有苗头了。

    你的文章方向很统一。

    Level1

    程序执行模型

    例如：

    • 栈
    • 寄存器
    • ABI
    • ELF

    Level2

    Toolchain

    • GCC
    • Linker
    • Loader
    • DWARF

    Level3

    OS

    • Process
    • MMU
    • Scheduler
    • VFS

    Level4

    BSP

    • Bootloader
    • Device Tree
    • Driver
    • PM

    Level5

    SoC

    • Cache
    • Interconnect
    • DMA
    • IOMMU

    未来五年就围绕这一棵树。

    不用东学一点西学一点。

    第八层：除了技术，我最推荐的五本书

    这些书对你未来影响可能比技术书还大。

    思考

    The Great Mental Models

    培养第一性原理。

    写作

    On Writing Well

    技术人最缺的是表达。

    结构化思维

    The Pyramid Principle

    以后汇报、写方案都能用。

    问题分析

    The Toyota Way

    根因分析思维。

    职业成长

    So Good They Can't Ignore You

    核心观点：

    不要追求热爱。

    先积累稀缺能力。

    这本书我觉得特别适合现在的你。

    最后说一句，从你最近几个月的问题来看：

    你真正的竞争力可能并不是 BSP。

    而是：

    你愿意不断追问「为什么」。

    你写 ELF、Linker、Stack、Backtrace 那些文章时，一直在问：

    • 为什么？
    • 从第一性原理看呢？
    • 如果没有DWARF呢？
    • Release和Debug本质区别是什么？

    这种思维方式，远比会不会某个驱动框架重要。

    所以对于公众号这件事，我会建议你：

    不要把它当赚钱工具。

    把它当你的「工程师成长日志」。

    未来三年，如果你能持续记录一个新人 SoC/BSP 工程师从 0 到 1 的真实成长过程，哪怕每篇只有几百阅读，长期价值都远大于追热点、追流量。

    因为三年后回头看，你最大的资产很可能不是公众号赚了多少钱，而是：

    你拥有了一套别人无法复制的知识体系
+
一批真正认可你技术的人
+
一个持续输出和思考的习惯

    而这三样东西，最终反而最容易转化成职业机会和收入。
